# 多文件与桌面集成

实现日期：2026-10-29。`useDocumentWorkspace` 管理会话，`DocumentTabs` 展示标签，`window_instance` 管理唯一主窗口和操作系统的文件打开请求。

## 文件与历史

- 新建、打开和文件管理器传入文件都增加标签，不替换当前文档，因此不要求关闭当前未保存内容。打开对话框支持多选。
- 规范化路径后去重，包括已存在文件的符号链接别名；重复打开切换到已有标签，不重新读盘。另存为不能覆盖另一个已打开标签的路径。
- 每个标签独立持有正文、保存基线、编码/BOM、磁盘版本、编辑模式、历史检查点、选区和滚动位置。切换前等待输入法组合及异步编辑完成，捕获纯数据后销毁原渲染器；恢复失败回滚，不丢弃文档。
- 仅当前标签挂载编辑器，后台没有 Muya/CodeMirror 实例。历史和文档结构仍占内存；切换需要复制检查点并重新布局，复杂图表会重新渲染。没有固定内存或切换时延保证。
- 撤销/重做、查找替换、大纲和统计作用于当前文档；同一文档切换源码模式继续保留原有跨模式历史语义。
- 全部保存分别使用各文件自己的编码和磁盘版本，失败时激活失败文件。关闭后台脏标签会先激活它，再以文件名询问保存、不保存、取消。关闭最后一个文件返回欢迎页。
- 关闭全部和退出先收集所有文档的内容版本批准，全部确认后才删除标签/备份。在较早文档选择不保存、较晚文档选择取消时，所有标签及未保存备份仍保留；已经明确保存的文件保持保存结果。
- 所有标签检查磁盘变化，仅活动标签弹出外部修改询问；后台显示冲突标记。重复同一外部版本不重复询问，普通保存仍做版本校验。
- 每个文档独立备份。恢复记录增加标签，原路径已打开或磁盘版本变化时恢复为未保存副本。正文/视图可跨进程恢复，运行期撤销历史暂不持久化。干净文件列表不作为下次启动工作区自动恢复。

## 单窗口与文件打开方式

使用官方 [Tauri single-instance 插件](https://v2.tauri.app/plugin/single-instance/)。依赖选用与当前 Tauri 兼容的 `tauri-plugin-single-instance ~2.4.5`；加入前核对 crates 元数据与官方仓库清单，Cargo.lock 固定实际版本。未新增 JavaScript 依赖。

- 首次启动从命令行接收路径；运行中再次启动会把参数和发送进程的工作目录转发到已有实例，然后显示、取消最小化并聚焦主窗口。
- 仅维护标签为 `main` 的主窗口。macOS 同时处理系统 Opened/Reopen 事件。原生退出菜单进入前端统一确认流程；确认关闭期间到达且尚未处理的打开请求使主进程保留并重建一个主窗口。
- 原生队列独立于 WebView，事件只负责唤醒。前端先注册监听再拉取队列，逐请求处理后按 ID 确认；渲染器启动前和旧窗口关闭期间的请求不会因事件监听尚未建立而被直接消费。请求处理失败显示文件错误，其余路径继续处理；处理通知失败保留请求并提供重试。
- 空参数再次启动只聚焦窗口；相对路径基于发送进程工作目录解析。接受本地 `file://` URL，保留空格、中文和 `#`；其他 URL 不转为本地文件读取。以 `-` 开头的文件名可放在 `--` 后。
- 安装器声明 `.md`、`.markdown`、`.txt` 文件关联。Linux 自定义 `.desktop` 的 `Exec=marknext %U` 接收文件管理器 URL，包含 `text/markdown;text/plain` MIME 类型；DEB、RPM 和 AppImage 复用此模板。Windows/macOS 由 Tauri 安装包生成文件关联元数据。

文件关联需使用重新构建的安装包安装后验证。开发态 `pnpm tauri dev` 不会自动注册文件打开方式。系统默认程序仍由用户在“打开方式”设置中选择；本实现不改写用户的默认关联。

## 手动验收

1. 打开两份含公式/列表的文档，分别编辑、撤销并切换源码模式；来回切换确认正文、模式、选区、滚动和两份撤销历史各自保留。
2. 编辑未保存时新建及打开文件，应增加标签；关闭脏标签分别选择取消/不保存/保存，确认只影响该标签。关闭最后一页回到欢迎页。
3. 两份文档都修改后退出，第一份选不保存、第二份选取消，两份应仍可继续编辑；再退出并全部确认，正常关闭。
4. 在别的程序修改后台文件，回到 MarkNext，后台仅有标记；激活它才询问是否加载。选保留后内容和保存保护不被改变。
5. 安装新包，通过文件管理器“打开方式 → MarkNext”打开含空格/中文/`#` 的文件。应用未运行时启动打开，已运行时加入原窗口；最小化后重复打开应恢复原窗口并选中原标签，未保存编辑仍存在。
6. 通过命令行一次传入多文件及重复路径，只有一个窗口、每个文件一个标签；从不同目录传相对路径仍应找到正确文件。Linux 示例：`marknext '/tmp/文档 # 1.md' /tmp/second.txt`。
7. 文件读取或保存询问尚未完成时从文件管理器打开另一文件，完成原操作后应处理排队请求；取消原关闭后，旧的未保存文件仍在。

## 自动化覆盖与边界

- `documentTabs.spec.ts`（composable）覆盖会话隔离、多选/去重、编码、关闭事务、保存失败、恢复、磁盘冲突、回滚和外部请求等待。
- `nativeFileRequests.spec.ts` 验证先监听后获取、请求确认、启动/运行期间的到达、重试和卸载。
- 浏览器 `documentTabs.spec.ts`、`nativeFiles.spec.ts` 挂载真实 App/Muya/CodeMirror，验证独立历史及销毁、源码光标/滚动、多草稿恢复、关闭保护、标签键盘/右键/中键和原生请求交付。
- Rust 测试验证本地路径/URL 解析、规范化、队列按 ID 确认和安装器配置；发布构建验证原生链接，Linux DEB 可解包检查实际 `.desktop`。

浏览器测试的 Tauri IPC 使用官方 mocks，不等于真实文件管理器/窗口管理器测试。Windows/macOS 原生焦点及安装后关联需在各自系统按上述步骤验收；Linux 的原生单实例与最终桌面关联也应使用实际安装包验证。
