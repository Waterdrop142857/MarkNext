# 文档会话与编辑历史接口设计

状态：多文件实现已接入，2026-10-29。接口位于 `src/editor/sessionTypes.ts`；两个适配器、`EditorSession.vue`、多文档仓库及标签页已实现。桌面文件接收与单窗口维护见 [多文件与桌面集成](multi-file.md)。
本文约束后续历史抽象及多文件实现；`ARCHITECTURE.md` 中早期标签页和模式切换草案以本文为准。

## 目标与范围

后台文档保留内容、历史和视图检查点，允许销毁 Muya/CodeMirror 渲染实例。恢复后继续撤销、重做，保留未保存内容、编辑模式和可恢复的选区。文档切换不构成编辑操作，不改变保存基线，不触发保存询问。

标签切换通过组件 API 完成捕获、销毁、重建闭环，后台标签仅保留文档和纯数据检查点。保留当前跨模式撤销语义：源码编辑阶段回到 Muya 时成为一个独立撤销步骤。本文不引入全新的跨引擎逐次操作栈，也不把运行期历史直接加入现有草稿恢复文件。

## 当前代码依据

- `src/muya/history/index.ts` 已导出可序列化历史，包含 undo/redo、选区历史、批次时间；栈深默认 100，按 JSON 操作记录。
- `src/muya/muya.ts` 已提供 `getState/getHistory/setHistory/flush`；`getState` 返回深拷贝。初始化支持 `options.json`，可直接恢复结构状态，避免重新解析 Markdown。
- `src/muya/editor/index.ts` 的 `setContent` 会清空历史。恢复必须先载入内容再导入历史；恢复过程不能走 `replaceContent`，否则会新增用户撤销步骤。
- `SourceEditor.vue` 普通外部内容更新仍会 `setValue` 并清空历史；现已通过 getHistoryAdapter 提供专用恢复路径，避免随后又被 v-model watcher 清空历史。
- 本地 CodeMirror 5 的 `getHistory()` 输出 `done/undone`，包含文本变更和选区事件。其类型声明返回 `any`，适配器边界必须进行明确结构校验与深拷贝，不能把 `any` 传播给会话层。
- 原 App 中进入源码前的 Markdown/选区边界已迁移至 EditorSession，在回到 Muya 时仍调用 `replaceContent`。单独保存当前活动编辑器的历史不足以恢复这个边界。

## 数据所有权

每个文档的正文和保存状态由 `useDocumentState` 持有；标签协调器保存后台文档的纯数据检查点。后台文档不持有编辑器、DOM、块实例、TextMarker、CodeMirror.Doc 或其回调与订阅。文档身份用 ID 表示，不能使用可变路径作为键。保存基线和磁盘版本属于文档会话，不属于历史栈；撤销是否回到已保存内容仍通过正文与保存基线比较。

`EditorSessionCheckpoint` 包装两类引擎检查点。每份检查点必须原子捕获精确正文、引擎数据、历史、选区和滚动位置。Muya 额外保留精确 `TState[]` 和影响解析的选项；源码历史依赖精确文本及换行配置（检查点保存 lineSeparator），禁止在捕获与恢复之间 trim、格式化或统一换行。

运行中的适配器持有实时状态；已提交检查点是不可变的快照，可能暂时落后于当前运行状态。销毁前必须提交新检查点。尚未激活的文档可以没有检查点；编辑过的文档不得以空检查点挂起。捕获过程进行深拷贝并递归冻结检查点。递归的 Muya 原生状态和历史类型保留引擎定义，避免 TypeScript 无限展开 JSON 操作类型；运行时冻结保证其内部也不可变。恢复时重新复制，不能把冻结数据交给可变引擎直接操作。

大数据放入非深响应式存储，例如普通 Map 配合 shallowRef。正文编辑不应对整个历史栈进行深监听、序列化或复制；捕获发生在挂起、必要模式切换或显式请求时。

## 统一历史接口

`EditorHistoryAdapter<Checkpoint>` 为 Muya 和 CodeMirror 提供相同的 status、undo、redo、flush、breakHistoryGroup、capture、restore、destroy 方法。两种适配器保留各自的历史格式，通过泛型约束检查点类型。

- `status()` 查询当前撤销/重做操作数及输入法组合状态。源码计数使用 historySize，不能用包含选区事件的数组长度代替。
- `capture(identity)` 同步完成 flush、输入分组合并边界截断和深拷贝，返回检查点。遇到输入法组合、正在提交的编辑事务或已销毁实例时显式失败；flush 导致预期修订发生变化时返回 mismatch，由控制器读取新修订后重试，禁止给新内容盖上旧修订号。失败时禁止销毁。
- `restore(checkpoint, expected)` 校验文档 ID、修订号、版本、引擎、解析选项和引擎数据格式，恢复过程禁止发出用户编辑通知或记录历史。异常由上层挂载事务捕获；失败后销毁临时目标实例，源会话保持可恢复。
- `undo/redo` 只作用于已挂载且匹配活动租约的适配器，输入法组合或恢复事务中返回 false。无渲染器时会话只保存数据；UI 命令先激活对应文档，再执行适配器操作。
- `destroy()` 幂等。应先标记租约失效，再清理回调、订阅、观察器、图表、资源和浮层，最后释放实例引用。销毁不能通过事件回调再修改会话。

`DocumentRevision.revision` 是文档内容的单调修订号，撤销也增加修订号；文件路径、主题、语言、字体、缩放、选区移动和标签激活不改变它。渲染租约使用独立的 activation 序号，处理同一文档相同修订被多次挂载的情况。保存操作携带文档 ID、内容修订和内容快照，异步结果只回写发起文档。

## 源码模式桥接

会话检查点使用明确的两种状态，禁止靠一组可空字段猜测模式：

| 模式 | 活动检查点 | 额外保留 |
|---|---|---|
| 所见即所得 | 当前 Muya 状态与历史 | 可选源码检查点；文本仍精确匹配时才复用源码历史 |
| 源码 | 当前源码文本与历史 | 进入源码前的 Muya 检查点，以及当时传给源码编辑器的精确文本 |

源码模式下，活动源码检查点与文档当前修订一致；桥接 Muya 检查点允许是更早修订，但必须属于同一文档。桥接源文本是进入源码时实际载入的文本，不假定它和 Muya 再次导出的字符串逐字相同。

进入源码：flush Muya，捕获基线与选区，载入源码文本；若缓存源码检查点与即将载入文本精确一致，恢复其历史，否则创建干净源码历史。新的桥接始终使用当前 Muya 基线，不能复用旧桥接。

源码后台挂起：同时保留活动源码检查点与桥接 Muya 检查点，销毁所有渲染实例。再次打开该文档只恢复源码渲染器，不预先构造隐藏 Muya。

退出源码：在临时 Muya 上恢复桥接状态、历史和进入源码前选区；源码内容变化时，通过现有 `replaceContent` 提交为单个撤销步骤。成功后才切换活动模式；失败时保留源码实例、全部内容与桥接，不更新保存基线。之后的 Muya 编辑使旧源码文本不匹配时，旧源码历史失效，不能仅更新其修订号假装兼容。

首阶段只保证文字选区恢复。表格矩形、图片等特殊选择应单独增加可序列化视图类型；无法恢复时使用安全文字光标并返回 view=fallback，不能影响正文和历史。源码保存所有选区及主选区索引。

## 挂起和恢复事务

生命周期：`uninitialized → mounting → active → suspending → suspended → mounting`。关闭文件经过统一保存保护后进入 disposed。模式切换与标签切换由上层控制器串行执行；快速重复请求合并或顺序处理，不允许两个目标同时成为 active。

挂起步骤：

1. 输入法组合期间保留切换请求，等待 compositionend 与本次输入事务结束；不伪造 compositionend，不强行丢弃正在输入的文字。若焦点移动已结束组合，仍须等待编辑队列提交完成。
2. 阻止新的修改命令；同步 flush，核对目标文档和当前租约。
3. 截断合并边界，原子捕获活动引擎及必要源码桥接数据；不得依赖下一帧才生成历史。
4. 由会话仓库核对文档 ID/修订号并提交检查点；捕获期间如发生内容变化则重试，失败保留实例。
5. 提交成功后使旧租约失效，清理搜索高亮和浮层，销毁适配器并清空 App/组件对旧编辑器的引用。

恢复步骤：

1. 捕获目标文档和新租约；加载准确的检查点，先进行格式及身份校验。
2. 创建不接收输入、不发出模型变更的目标实例。Muya 直接用 json 初始化；CodeMirror 先载入精确文本。CodeMirror 的 setSelections 会记录选区历史，因此必须在最终导入历史之前恢复选区，或者显式隔离这次原生历史记录；不能让恢复动作污染导入的 undo/redo。
3. 导入历史时截断输入分组，不能沿用上次捕获的墙钟时间与输入类型合并下次操作。Muya 已提供 breakGroup，同时重置时间与 `_lastInputKind`。
4. 恢复选区和布局完成后的滚动位置，应用最新外观设置；失效选区降级为安全光标。布局任务必须核对租约。
5. 核对最新活动请求，成功后才发布 ready 并允许输入。恢复失败销毁临时实例，保留原检查点；不得静默清空历史后声称恢复成功。允许用户明确选择仅恢复正文作为错误恢复路径。

恢复必须发生在 Vue model watcher 正常同步之前，或者通过专用 restoring 状态屏蔽 watcher；不能在下一次 tick 又执行 setContent/setValue 清空刚恢复的历史。UI 的只读切换和恢复不得产生 dirty 标记、保存、重新加载或新的撤销项。

## 资源与性能

销毁目标涵盖 DOM、全局与局部事件、RxJS 订阅、requestAnimationFrame、定时器、Resize/IntersectionObserver、WebKit 选区绘制、异步图片/剪贴板/图表回调、Vega view 和 document.body 浮层。Muya 当前 destroy 已做部分清理，但不能据此假设所有资源已释放，必须逐项验证。

后台仍占用正文、结构状态和历史操作内存；大段删除的逆操作会保留大文本，因此“100 条历史”不代表固定内存。首阶段保留现有引擎深度，记录检查点大小和捕获耗时；不擅自截断用户历史。后续按测量结果设计历史字节预算及近期实例缓存。

切换时存在重建布局及公式/图表的成本。只渲染目标文档的活动模式，默认不为后台文档重建编辑器。近期实例缓存是可选优化，其淘汰条件与纯数据检查点协议一致，不能成为正确性前提。首次验证不在每次输入时进行 JSON.stringify，也不在每次切换时额外计算全文哈希。

现有草稿恢复优先保证正文与保存基线可靠；运行期检查点保持内存格式。跨进程持久化历史需要额外的引擎版本兼容、结构校验、大小限制及失败恢复策略，后续单独实现。

## 验收矩阵

- 两种引擎：有 undo 和 redo 的情况下捕获，销毁旧实例，在全新实例中继续两种操作，最终内容及结构一致；快照经 JSON 往返仍可恢复。
- Muya：段落、标题、嵌套列表、表格、公式、前置信息、结构变更、非折叠选区；检验原始 JSON 状态对应关系。
- CodeMirror：空文本、连续空格、CRLF、多行替换、多选区、搜索高亮；恢复后导入历史不触发额外正文更新。
- 同一帧输入后立即挂起、组合输入中切换、快速连续激活请求；不得丢最后一次修改或让旧回调写入新实例。
- 源码模式中挂起恢复后返回 Muya，先一步撤销整个源码会话，再继续撤销之前的 Muya 编辑；无源码修改时不增加步骤。
- 错误文档/修订/引擎/版本、损坏历史、恢复异常：拒绝并保留可恢复内容；无效选区只降级视图。
- 重复挂起恢复与销毁：DOM 浮层、事件、订阅、定时任务和图表实例不持续增长；销毁后不存在对旧会话的晚到写入。堆快照辅助检查，不以不稳定的 GC 计时作唯一自动化断言。
- 用户操作回归：保存、另存为、取消关闭、外部修改保护、草稿恢复、搜索、统计/大纲和外观设置行为不退化。

性能验收先记录代表性小文件、大文件与公式/图表文件的捕获时间、恢复时间和后台资源，再确定缓存策略；不提前宣称恒定切换速度或固定内存节省比例。


## 当前实现入口与约束

- `MuyaHistoryAdapter` / `SourceHistoryAdapter` 实现统一历史接口；`checkpointCodec` 校验纯数据、结构、历史操作路径和文本偏移。未知版本或不匹配的身份在恢复前拒绝。
- `EditorSession.vue` 已接入 App，普通模式切换继续复用实例，避免不必要的重新渲染。`capture()` 返回纯数据；`suspend()` 成功捕获后销毁渲染器；`resume()` 恢复本会话。通过初始 `checkpoint` prop 可在整个旧会话组件销毁后，在新组件中恢复同一文档。
- `suspend()` 遇到输入法组合等待结束，遇到 Muya.trackTask 标记的粘贴/图片处理等待 async-idle；销毁组件会取消等待。直接调用适配器 capture 时，未完成的异步编辑返回 busy。
- 每个文档用独立的内容修订号标识编辑，字体、语言、缩放和滚动不改变修订。每个 workspace 独立维护磁盘版本、编码、保存基线与写入队列；活动渲染器的 generation 和文档身份隔离异步回调。
- 后台检查点不持有 DOM；组件负责清理 WebKit 选区绘制、图片上下文、窗口 resize 和 CodeMirror 输入焦点。Muya 额外取消待提交 JSON 帧，注销输入 RxJS 订阅，销毁幂等；异步粘贴、拖放、HTML 图片回调和延迟光标更新检查销毁状态。
- Muya 的滚动检查点读取 `.muya-editor` 包装层；CodeMirror 在重新显示并完成 refresh 后应用保存的滚动位置，避免隐藏期间被裁为零。
- 不提供用户可见的挂起按钮，挂起由标签切换自动调度。新建和打开增加标签；关闭标签、关闭全部及退出统一执行保存保护。

运行 `src/editor/__tests__` 检查适配器与会话逻辑；`tests/e2e/editorSession.spec.ts` 通过独立测试入口加载真实组件验证浏览器布局、滚动、输入法等待和重建。测试入口未被生产 main.ts 引用。
