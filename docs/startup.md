# 启动显示与编辑器加载

启动流程分为轻量启动页、应用外壳、编辑器三层：

1. `index.html` 的经典脚本 `public/startup.js` 在解析正文前读取主题，遵循既有的 light/dark/system 偏好和 light 默认值。内联 CSS 先绘制相同主题的背景与软件图标，不依赖 Vue、编辑器 CSS 或 Web 字体。
2. `main.ts` 读取原生窗口的启动代号，再动态导入 App。App 挂载并完成 Vue 更新和布局后，通过 `startup_ready` 通知原生层。主窗口最初隐藏，原生层先设置相同主题的 WebView/窗口背景，再显示窗口。显示成功后移除启动页。
3. 欢迎页不加载 EditorSession。新建、打开、草稿恢复和原生文件队列首次激活文档时，`prepareEditor` 等待编辑器模块及其 CSS 就绪，再挂载、恢复历史检查点。模块加载失败保留文档并返回原会话；首次加载完成后复用模块，不重复下载。

隐藏的 WebView 可能暂停 requestAnimationFrame，因此显示握手不依赖 rAF。草稿列表读取和初始文件解析也不作为显示应用外壳的前置条件。

## 单窗口与失败恢复

- 第二次启动和 macOS Reopen 在窗口尚未就绪时不会提前调用 show。文件请求仍保存在 Rust 队列中；外壳就绪后显示窗口，编辑器准备好后继续打开文件并逐项确认。
- 每次页面加载和主窗口重建使用新的启动代号。旧页面的就绪通知和旧看门狗不能显示新窗口。
- 模块载入失败显示中英文重新加载入口。即使前置主题脚本不可用，正常启动也会清理遮罩，错误路径仍可显示重试入口。
- 原生看门狗在 8 秒内未完成显示时尝试显示错误页，避免只剩隐藏进程。正常就绪后及窗口销毁后，旧看门狗不再处理该窗口。
- 启动错误及重新加载不删除任何草稿恢复记录。
- 关闭启动错误页会取消尚未处理的文件打开请求，允许进程正常退出，避免保留请求的窗口重建逻辑反复弹出错误页。已保存的草稿恢复记录不受影响。

## 验证

`src/services/__tests__/startup.spec.ts` 核对主题与 useTheme 一致、存储不可用、错误显示与清理、原生代号及隐藏窗口无需等待 rAF。

`documentTabs.spec.ts` 补充懒加载等待和失败重试，原有会话隔离、关闭保护、历史恢复测试继续适用。

浏览器 `tests/e2e/startup.spec.ts` 在开发与生产入口分别延迟 App，检查浅色/深色启动背景；确认欢迎页不请求编辑器、新建才加载；另覆盖失败重试、前置脚本丢失和冷启动原生文件请求。

Rust `StartupGate` 测试覆盖就绪前禁止显示、代号失效、看门狗及错误窗口重新聚焦；安装配置测试要求主窗口初始隐藏。

本地可用 `pnpm tauri dev` 或安装包检查：深色/浅色/跟随系统、空窗口启动、文件管理器冷启动/重复打开、最小化后激活及启动失败重试。确认标题栏/菜单出现时已经使用正确主题，随后打开文件仍保留独立历史。
